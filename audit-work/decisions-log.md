# CrawlForge: Decisions Log

Product decisions made by the owner (Lionel) during the post-build audit. These are authoritative inputs for the gap register (`register/`), spec amendments and the build-plan extension. Where a decision changes the functional specification, it must be carried into a spec amendment.

| ID | Date | Decision | Consequences |
|---|---|---|---|
| D-001 | 2026-11-17 | **JS and non-JS crawls are both required.** Capture modes: non-JS only, JS only, dual (both with comparison), adaptive (render per template only where needed). | See `project-configuration-review.md` section 4.2. Register: CAP-A-X09. |
| D-002 | 2026-11-17 | **Drive Chrome DevTools Protocol directly**, replacing PuppeteerSharp, as part of the rendering rebuild now. | Section 4.3. Register: CAP-A-X10. Large job for a Claude Code session. |
| D-003 | 2026-11-17 | **Bundle a pinned Chrome for Testing build** (full build, headless), with configured path and local Chrome/Edge as fallbacks. | Section 4.4. Register: CAP-A-X11. |
| D-004 | 2026-11-17 | **CrawlForge is a general-purpose crawling and auditing utility**, not a differentiator-led "intelligence platform". Feature parity and reliability come first. | Checklist scope; positioning material excluded from audit documents. |
| D-005 | 2026-11-17 | **Google Search Console and GA4 integration are required.** | Checklist rows 181 and 182 become required (not "Not applicable"). Spec amendment needed: §2.6 network boundary must allow user-connected Google APIs, user-initiated or scheduled sync only, off by default, data cached locally so audits work offline after sync. Open sub-decision: OAuth client (bring-your-own Google Cloud client vs shipped client requiring Google verification). Offline CSV import (CAP-A-X08) remains as fallback. |
| D-006 | 2026-11-17 | **Email reports are not needed.** | Checklist row 189 out of scope by decision. |
| D-007 | 2026-11-17 | **A local fixture test site with known traps is part of the build-plan extension**, and acceptance for each end-to-end flow runs against it. | Traps to include at minimum: redirect chain and loop, noindexed page, JS-only link, soft 404, postback link, hash route, client-side redirect, crawler trap, consent banner. "Done" means a real audit finds them. |
| D-008 | 2026-11-17 | **AI analysis is delivered through MCP.** CrawlForge does not host or call an LLM itself. External MCP clients (Claude, VS Code and others) are used both to steer CrawlForge (start, configure, control audits) and to analyse its data. | Section J capabilities are judged by whether the MCP surface gives a client the structured evidence and controls needed: read tools for findings, URLs, links, templates, comparisons; steering tools for projects, configurations and audit lifecycle; prompts/briefings; evidence references on every result. The "AI never invents findings" rule is met by design. Spec as written already allows local MCP clients (no network amendment needed). Requires working stdio transport for VS Code / Claude Desktop and safe authorisation for steering actions. |
| D-009 | 2026-11-17 | **CrawlForge is the owner's own tool first, with the intent to make it available later to other SEO specialists** (people currently paying for Sitebulb or Screaming Frog premium). | Build for single-user desktop use now, but do not foreclose distribution. Multi-user access and permissions (row 191) out of scope: one user per install. OAuth (D-005): bring-your-own Google Cloud client now, behind an abstraction so a shipped, Google-verified client can be added later. Pinned bundled browser (D-003) gains priority for consistent results across machines. Distribution prerequisites to record as future spec items, not current build work: licensing or activation (currently excluded by spec §3 and §4.1), an update channel (spec §2.6 forbids update checking), Windows code signing, an installer, opt-in crash reporting, and possibly macOS support. |
| D-010 | 2026-11-17 | **CrawlForge will be distributed as open source.** | Supersedes the licensing/activation item in D-009: no licence keys, entitlements or accounts are needed, which is consistent with spec §4.1. Remaining distribution prerequisites: an update channel (for example GitHub Releases, user-triggered check; spec §2.6 needs amending), Windows code signing (free signing programmes for open-source projects exist), an installer, opt-in crash reporting, possibly macOS. New work required: a licence audit of every dependency and every bundled asset before first public release (see O-005, O-006). |
| D-011 | 2026-11-17 | **Licence: AGPL-3.0, with a contributor licence agreement (CLA) required from the first outside contribution.** | Users and agencies running CrawlForge (including for paid client work) have no obligations; anyone offering a modified version as a network service must publish their changes. The CLA keeps the owner's option to relicense or offer commercial terms later. Admin: LICENSE file, README notice, optional source headers, CLA document plus a CLA-check bot on the repository before accepting contributions. Dependencies under MIT/Apache are compatible. Licence audit (O-006) still required before first public release. |
| D-012 | 2026-11-17 | **PageSpeed Insights integration is required**, on the same terms as GSC: the user supplies their own free API key, and it runs only when triggered. | Checklist row 183 required. Adds real-user (CrUX) field data alongside the local Core Web Vitals lab probe. Covered by the same §2.6 network-boundary amendment as D-005. |
| D-013 | 2026-11-17 | **Webhooks are not needed.** The MCP connection covers the use case. | Checklist row 187 out of scope. MCP must expose audit status and completion tools so a client can check or wait for an audit to finish. Scheduled-audit OS notifications remain for unattended runs. |
| D-014 | 2026-11-17 | **Agent data contract.** Summary-first, paginated JSON over MCP (counts and top issues first, filtered pages, single-record detail; stable IDs and cursors on every result). Bulk files for agents working in code: CSV for flat tables (URLs, links, findings), JSON Lines for nested records, Markdown for page content. A read-only SQLite snapshot of an audit with a documented schema. No YAML for crawl data. | Checklist rows 185 and 186. Applies to MCP tool design and to export formats. |
| D-015 | 2026-11-17 | **Capability spine adjusted** (closes O-004): directive-handling toggles and resource/external scope toggles promoted to their own capabilities (CAP-A-X21, CAP-A-X22); new sections K (Projects and configuration) and L (Platform) hold configuration and platform extras moved out of H; remaining H extras renumbered; decisions D-005, D-006, D-008, D-009, D-012, D-013 and D-014 recorded on the affected capabilities. | `register/capabilities.yaml`: 275 capabilities (213 checklist, 62 extras), validator passes. No findings existed yet, so no references broke. |
| D-016 | 2026-11-17 | **Strong client-side application (SPA) support from the start, including click discovery.** Prompted by difficulty crawling betting sites. | Click discovery specified in architecture §5.6.4 (CR-009) with mandatory safety: non-GET/HEAD requests blocked, destructive-action pattern list, no form filling. Wait rule ignores long-lived streaming connections. |
| D-017 | 2026-11-17 | **Change-record review batch 3.** Integrations get per-project toggles for each integration and data type. Cloud export destinations out of scope for now (local folder, FTP, SFTP only). CR-017 scope decisions accepted as suggested: 9 in (template identification and template grouping, segments, RDFa, cookie security, information disclosure, plain-text export), 3 via MCP, 1 out (XML export), 17 deferred. | Architecture v2.0 now specifies or explicitly excludes every register capability: 251 tagged, 24 deferred / out of scope / via MCP. All change records CR-001 to CR-017 applied. |
