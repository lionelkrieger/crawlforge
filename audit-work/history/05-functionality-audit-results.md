### The 15 most important gaps for a general-purpose crawling and auditing utility (ranked)

1. **Row 4** — JavaScript-rendered crawling does not happen in full audits: the rendering pool is never injected into `AuditExecutionEngine`, so `RenderedDocument` is always null and SPA content is never crawled or audited (G03).
2. **Rows 168–171** — The entire reporting layer is unreachable: dashboards, URL inventory, filtering and segmentation are implemented and API-wired but no component mounts them, leaving users with a text placeholder (G01).
3. **Rows 82–84, 88–89** — Core Web Vitals (LCP/INP/CLS) and CSS/JS code-coverage analyzers are complete but dead code with zero DI registrations or production callers (G04).
4. **Rows 39–42** — The most basic SEO metadata checks are absent: there is no missing-title, duplicate-title, missing-description or duplicate-description rule or site pass anywhere (G12).
5. **Rows 46–47** — Broken internal and external link detection does not exist: link edges are stored but never correlated with fetch failures, and external links are never fetched (G12).
6. **Rows 8, 52–54** — Sitemap ingestion is entirely missing, so sitemap discovery and missing/non-indexable/redirecting-URL checks cannot be performed; only sitemap *generation* exists (G08).
7. **Rows 21–24** — Authentication, cookies, custom headers and proxy are implemented in `HttpFetcher` but the engine supplies none of them, so authenticated and proxied crawls are impossible in a real audit (G09).
8. **Rows 111–118** — There is no security audit capability at all: all eight security rows are spec-only because the rule taxonomy has no Security category (G12).
9. **Rows 153–161** — Custom extraction and search rules never execute in a real audit because `CustomExtractionRulesJson` has no production writer in the configuration API (G13).
10. **Rows 67–68, B2 69–80** — Structured-data validation is confined to a standalone tool and never runs as part of an audit, so no per-audit structured-data findings or explorer exist (G11).
11. **Row 140** — Near-duplicate content detection is a fully written shingle detector with no registration or caller — pure dead code (G23).
12. **Rows 173–177** — CSV/XLSX/PDF/HTML export writers are wired and API-reachable but no mounted UI can trigger an export, and JSON/plain-text/Markdown export formats do not exist.
13. **Rows 199–202** — Change detection is incomplete: score deltas are computed then dropped from the wire response, structural/disappearing-content detection is single-URL only, and no comparison UI exists (G01, G05).
14. **Rows 193, 195, 197–198** — Findings cannot be prioritised by affected-URL count, confidence, template or root cause because those models do not exist; priority/remediation-effort values are buried in evidence JSON (G01).
15. **Rows 185, 187–188** — MCP enable/token settings are disconnected from the running server, and scheduled crawls and webhook delivery have no UI, so automation cannot be managed from the product (G17, G01).

## 5. Method notes

- Read-only audit: no builds, installs, migrations, app launches, commits, or file modifications were performed. Only this output file was written.
- Search hygiene: `bin`, `obj`, `node_modules`, `dist` were excluded from all recursive searches.
- The three prior inventories (`01-api-exposure-inventory.md`, `02-ux-surface-inventory.md`, `03-documented-feature-inventory.md`) and `UNDERBUILD-AUDIT.md` were read first and reused, not redone or edited.
- Four independent layers were assessed per row: Engine (production implementation), Wired (registered AND invoked in a real audit/request), API (route or MCP tool), UI (mounted/reachable control). Existence of a class/component is not wiring; an unmounted component is not UI.
- Unit tests were not treated as evidence of implementation or wiring; they are cited only as supporting notes.
- Be conservative: where wiring could not be confirmed, notes say "wiring unconfirmed" and the row was not marked Implemented.
- Design exclusions: the offline-first, single-user, zero-outbound design (and the five open scope decisions in `02-open-scope-decisions.md`) make GSC/GA4/PageSpeed/email/multi-user integrations intentionally absent; these are recorded as Not applicable with rationale.
- Not verified: live runtime behavior (no app/build run permitted by the audit brief); all wiring conclusions are from static code tracing.
