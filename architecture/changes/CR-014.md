## Rationale

D-009: own tool first, made available to other SEO specialists later; D-010: open source; D-011: AGPL-3.0 with CLA. Distribution needs an installer, signing, a release channel and a licence audit. These are future spec items, not current build work, but recording them now prevents the architecture from foreclosing them.

## Proposed text (new file)

> **1. Installer.** A per-user Windows installer that installs the shell, backend, bundled assets and pinned browser (CR-007), and uninstalls cleanly while leaving user data unless the user chooses to remove it.
>
> **2. Code signing.** Release binaries and the installer are code-signed so operating-system reputation checks do not warn users. A signing programme for open-source projects may be used.
>
> **3. Release channel.** Releases are published with release notes on the project's public release channel. A user-initiated release check (CR-003) compares the installed version with the latest release; installation is manual or user-confirmed. No automatic checking.
>
> **4. Crash reporting.** Crash reporting stays local (minidumps, §3 row 6). Any opt-in crash submission is a separate future decision and would require amending §3 row 6.
>
> **5. Licence audit.** Before every public release, every bundled dependency and data asset (including dictionaries, the ONNX model, technology fingerprints, WAF signatures, bot IP lists, AI agent profiles, font metrics, stop-word lists and the pinned browser) is checked for redistribution terms and compatibility with AGPL-3.0. Incompatible items are replaced or removed before release.
>
> **6. Platforms.** Windows is the release platform. macOS support is a future decision; architecture decisions must not hard-code Windows-only behaviour where a portable choice exists.

## Open questions

1. Release channel: GitHub Releases (proposed)?
2. Opt-in crash reporting: in scope later or never?
3. macOS: when, if at all?
4. Large assets (87 MB ONNX model): ship in installer or download-on-demand from the release channel (which would need a network-boundary amendment)?
