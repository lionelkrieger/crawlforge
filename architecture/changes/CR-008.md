## Rationale

## Proposed text

**§5.1 inputs table gains rows:** Cookie handling; Directive handling; Resource and external scope; Crawler-trap detection; User-agent comparison (each "No", referencing the sections below).

> **§5.11 Per-audit cookie jar.** Cookies set by crawled sites are retained for the audit, scoped by host as a browser would scope them, and sent on subsequent in-scope requests. A configuration toggle crawls cookieless instead. User-supplied cookies (§5.1) are merged in. When a URL's response changes after a cookie was set, the change is recorded.
>
> **§5.12 Directive-handling toggles.** Per configuration: follow `nofollow` links (page level and link level, separately); crawl pages marked `noindex`; follow canonical targets as discovery; use hreflang alternates and rel next/previous as discovery; follow iframes; follow meta refresh. Defaults follow search-engine behaviour unless the user changes them. Detection and reporting of these directives (§7.3, §7.4) is unaffected by the toggles.
>
> **§5.13 Resource and external scope.** Per configuration: fetch toggles for each resource type (scripts, stylesheets, images, fonts, other files); a list of asset domains (for example CDNs) treated as internal; and a toggle to check the status of external links without crawling beyond them.
>
> **§5.14 Crawler-trap detection.** The engine flags URL patterns whose count grows without new content: parameter-combination explosion, repeating path segments, incrementing date paths, and runs of near-duplicate content hashes. A flagged pattern is throttled and raised as a finding naming the pattern, its URL count and examples.
>
> **§5.15 User-agent comparison (optional).** A sample of URLs (or all URLs) is fetched both as a search-engine crawler and as a standard browser. Status, redirects, meta robots, canonical, content hash and links are compared; material differences are raised as findings (possible cloaking, dynamic rendering or bot blocking).

## Open questions

1. Defaults for each directive toggle (proposed: follow Google's behaviour).
2. Trap detection thresholds (how many URLs per pattern before flagging; similarity threshold).
3. UA comparison: sample size default, and which crawler UA string.
4. Cookie jar default on or off (proposed on).

## Impact

Configuration contracts (REST/MCP), configuration editor (CR-012), findings taxonomy (§7.4 gains trap and UA-difference rules). Fixture traps (CR-015): crawler trap, cookie-dependent redirect.
