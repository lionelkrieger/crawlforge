## Rationale

CR-015 and CR-018 say acceptance runs "through the UI or MCP", while probe-2 started audits via REST. The build plan conservatively required UI-started audits everywhere, which would make the full trap matrix slow.

## Change

Flow criteria #49, #55 and #56 must be proven through the UI at least once per run; the bulk trap matrix may use REST or MCP; workarounds never count.
