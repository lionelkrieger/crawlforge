## Rationale

The spec already says schedules use a recurrence rule, but the code exposes it as `ScheduleCreateRequest.Cron`, which rejects cron syntax. With an open-source release ahead, a `cron` field that is not cron would mislead users.

## Change

§6.1 names the wire field `recurrence`. Renaming the code field (with contract-conformance tests) is defect work for the schedules workpiece.
