## Rationale

D-005 and D-012 require user-connected Search Console, GA4 and PageSpeed Insights. D-009: own OAuth client now, behind an abstraction so a shipped, Google-verified client can be added later. §7.11 names field-data enrichment as an open scope decision; it is resolved here. Lighthouse results (CAP-C-081) and INP field data (CAP-C-083) arrive through PageSpeed Insights.

## Proposed text (new file `08-integrations/01-google-integrations.md`)

> **1. Connections.** Integrations are off by default. The user connects Google Search Console and GA4 through an OAuth flow using **their own OAuth client** (client ID and secret from their own Google Cloud project), and PageSpeed Insights through **their own API key**. The OAuth client is behind a provider abstraction so that a shipped client can be added later without changing the integration contracts. Credentials and tokens are stored encrypted at rest (section 9.1) and never leave the machine except to the respective Google API.
>
> **2. Property binding.** Each project binds at most one Search Console property and one GA4 property. Binding is explicit; nothing is inferred from crawled sites.
>
> **3. Sync.** Data is retrieved only when the user starts a sync or a schedule the user created triggers one. Synced data is stored locally per project and date range, so audits and reports work offline. Sync failures never fail an audit.
>
> **4. Uses in audits.** Search Console and GA4 page lists join crawl results by normalised URL to identify: pages with impressions or sessions that the crawl did not find (orphan candidates); indexed-but-not-crawlable and crawlable-but-not-indexed pages; and traffic-weighted prioritisation of findings. PageSpeed Insights adds Lighthouse lab results and real-user field data (including INP) per URL, alongside the local lab probe (section 7.11).
>
> **5. Offline fallback.** Without a connection, the user may import Search Console and GA4 page exports as CSV with the same join behaviour (CAP-A-X08).
>
> **6. Contracts.** REST, hub and MCP additions for connection status, sync start, sync progress and synced datasets, following the conventions of section 10 and section 11.

**§7.11, current bullet:** "Optional field-data enrichment from an external provider is an open scope decision (section 15) and is not required by this version."

**Replacement:** "Field data and Lighthouse results from PageSpeed Insights are available through the user-connected integration (08-integrations), when connected."
