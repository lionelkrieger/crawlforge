## Rationale

Every capability in the register must trace to the specification text that requires it, so build work can cite both and drift becomes detectable.

## Method

Each capability was matched to the most specific heading whose existing text specifies its behaviour, by reading the section content (not by title matching). A traceability line `> Capabilities: ...` was inserted directly under that heading. A capability is tagged only where the section genuinely specifies it; partial coverage is tagged where the core behaviour is specified, with the remainder carried in the relevant draft CR. `check_traceability.py` verifies the tags and generates `TRACEABILITY.md`.
