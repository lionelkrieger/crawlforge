## Rationale

D-007: acceptance for each end-to-end flow runs against a local fixture site with known traps; "done" means a real audit finds them. The first build reported every criterion complete while key subsystems were never wired, because criteria were satisfied by unit tests that supplied their own inputs.

## Proposed text

**New file `03-fixture-site.md`:**

> - A self-contained local website, served on loopback during tests, versioned with the product. Each page is a named **trap** with a documented expected outcome (expected findings, URL states and links).
> - Minimum trap set: redirect chain; redirect loop; noindexed page; robots-blocked URL; canonical conflict; broken internal and external links; orphan page (sitemap only); JavaScript-only link; content injected only by script; late title/canonical/robots change by script; soft 404 on a server page and on a client-side route; hash route; client-side redirect; postback link; cookieless-session URL; large ViewState; crawler trap (infinite parameter combinations and calendar); cookie-dependent redirect; consent banner with a tag firing before consent; service worker; structured data with errors; missing alt text; mixed content; hreflang without return tag; duplicate titles; thin page.
> - A machine-readable expected-results file lists, per trap, the findings and states an audit must produce.
>
> **Acceptance rule.** A criterion from #49 onward passes only when a full audit, started through the product's normal entry points (UI or MCP), against the fixture site, produces the expected results for the traps the criterion names. Unit tests alone never satisfy a criterion.

**New criteria (to be numbered from #49 when approved):**

> - **#49 HTTP flow.** Create project, configure, run a non-JS audit, view results grid, export CSV and XLSX: traps redirect chain/loop, noindex, robots-blocked, broken links, duplicate titles, thin page.
> - **#50 Rendered flow.** Same with JS capture: JavaScript-only link, script-injected content, consent banner.
> - **#51 Dual flow.** Raw-vs-rendered comparison: late meta change, script-injected content.
> - **#52 Adaptive flow.** Only JS-dependent templates switch to rendered capture.
> - **#53 Site types.** Hash route, client-side redirect, postback link, cookieless session, ViewState, rendered soft 404.
> - **#54 Crawl safety.** Crawler trap detected and throttled; cookie-dependent redirect handled.
> - **#55 Configuration editor.** A non-default configuration created and edited in the UI changes audit behaviour as configured.
> - **#56 MCP flow.** An MCP client creates a project and configuration, runs an audit to completion and reads paged findings with evidence.
> - **#57 Integrations.** GSC, GA4 and PageSpeed Insights sync and join against recorded API responses (test double), and the offline CSV import produces the same joins.
