## Rationale

D-008: AI analysis is delivered through MCP; external clients (Claude, VS Code and others) both steer CrawlForge and analyse its data. CrawlForge hosts no model. D-013: webhooks are replaced by MCP status and completion; §11.5 already specifies polling with retry hints and completion notifications, so nothing new is needed for that. D-014 defines the agent data contract. Today the MCP surface can run audits but cannot manage projects or configurations, and returns no bulk agent formats.

## Proposed text

**§11.3 gains steering tools** (each mapping one-to-one onto a REST operation, same rules as existing tools):

> | Tool | Input fields | Behavior | Output |
> |---|---|---|---|
> | list-projects / create-project / update-project | Project fields | Project management | Project record(s) |
> | list-configurations / get-configuration / create-configuration / update-configuration | Project reference; configuration fields | Configuration management, including capture mode and all section 5.1 inputs | Configuration record |
> | query-findings | Audit reference; filters (severity, category, rule, URL pattern, template); cursor | Paged finding rows with evidence | Rows, total count, next cursor |
> | query-urls | Audit reference; filters; selected columns; cursor | Paged URL rows | Rows, total count, next cursor |
> | export-agent-dataset | Audit reference; dataset; format | Writes a bulk dataset file (§11.8) to a local path | File path, row count |

**New §11.7 Summary-first responses.** Every data-returning tool and resource leads with counts and the highest-priority items, returns at most one page of rows, and carries stable identifiers (audit, URL, finding, rule) and a cursor. No tool returns an unbounded result set.

**New §11.8 Agent data contract.**

> - Over MCP: compact JSON, summary-first and paginated (§11.7).
> - Bulk files for agents working in code: **CSV** for flat tables (URLs, links, findings), **JSON Lines** for nested records (full URL records, structured-data entities, redirect chains), **Markdown** for page content.
> - A **read-only SQLite snapshot** of an audit, with a documented schema, may be exported for query by an agent. It contains no secrets or credentials.
> - Every exported row carries the same stable identifiers as the API.

**§11.5 guardrails gain:** "AI clients interpret only data CrawlForge has collected. The interface exposes no operation that fabricates or edits findings; every finding returned carries its evidence and source rule."

**§8.4 Export gains:** JSON Lines and Markdown dataset exports, and the read-only SQLite audit snapshot (§11.8).

**§11.6 credentials** apply unchanged to steering tools; configuration-changing tools are recorded in the action log like lifecycle tools.

## Open questions

1. Should steering tools that change configurations require an extra per-session confirmation, beyond the token?
2. Default and maximum page sizes.
3. §15 item 5 (raw-SQL administration tool): does the read-only SQLite snapshot resolve it, or stay separate?
4. VS Code and Claude connect over stdio (§11.2); any additional transport needed?

## Impact

REST contract (new endpoints for configuration CRUD already exist; confirm parity). Hub unchanged. Acceptance: an MCP client creates a project, configures it, runs an audit to completion and reads paged findings against the fixture site (CR-015).

## Resolutions (owner, 2026-11-17)

1. Settings switch "Allow MCP clients to change projects and configurations", on by default; token and action log unchanged.
2. Page size 50 default, 500 maximum.
3. §15 item 5 (raw-SQL tool) resolved by the read-only SQLite snapshot.
4. Transports: stdio and existing loopback; nothing new.

Applied with these resolutions. Where the applied text differs from the proposed text above, the applied text in the architecture is authoritative.
