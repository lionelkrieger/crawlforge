## Rationale

The backend exposes full configuration CRUD but no screen uses it; the only configuration UI creates a hidden default. Several per-project settings are unspecified. Analysis-category toggles exist but resolve app-wide.

## Proposed text

**New §8.8 Configuration editor:**

> - Every project lists its configurations (named crawl profiles, for example "Full crawl", "Quick sample", "Mobile rendered", "URL list check"). Each configuration can be viewed, created, duplicated, edited and deleted.
> - The editor exposes every section 5.1 input and the CR-005, CR-008, CR-009 and CR-010 settings, grouped: start URLs and scope; "crawl as" preset (user agent, viewport, capture mode); limits; include/exclude rules; directive handling; resources and external scope; authentication and cookies; analysis categories; thresholds; extraction and search; advanced.
> - App-level configuration templates can be copied into a project.
> - A running audit keeps the configuration snapshot it started with (section 4.3).
>
> **"Crawl as" presets** bundle user agent, viewport and capture mode: search-engine smartphone, search-engine desktop, standard mobile browser, standard desktop browser.

**§7.5, current text** "assigned by the rule definition, with thresholds configurable locally" **gains:** "Thresholds (title and description lengths, thin-content word count, slow-response cut-off, readability target and others) are configurable **per project**, falling back to application defaults."

**Analysis categories:** category enablement is resolved **per configuration**, not application-wide; a disabled category contributes no score (§8.1, unchanged).

**Client context (per project):** expected GA4 measurement IDs and GTM container IDs (used by analytics coverage checks, FS-CRAWL-002 §14), expected consent platform, brand name variants, target locale and language (drives spelling dictionary and expected hreflang), and report branding (client name, logo).

**§9.5 Retention gains:** per-project retention (keep last N audits or by age) and a choice to store full documents or extracted data only, with disk usage shown per project.

## Traceability

## Open questions

1. Default threshold values (take from current rule definitions?).
2. Exact preset list and user agent strings.
3. Should client context live on the project or on a separate "client" entity shared by projects?
4. Retention defaults.

## Impact

Schema (project settings, client context), REST and MCP configuration contracts (CR-011), UI. Fixes the confirmed gap that configurations are invisible. Acceptance: create, edit and run a non-default configuration end to end (CR-015).

## Resolutions (owner, 2026-11-17)

1. Threshold defaults taken from current rule definitions.
2. Presets: Googlebot Smartphone, Googlebot Desktop, Chrome mobile, Chrome desktop.
3. Client context on a **shared client entity** used by several projects, with per-project override.
4. Retention default: last 10 audits per project with full stored documents.

Applied with these resolutions. Where the applied text differs from the proposed text above, the applied text in the architecture is authoritative.
